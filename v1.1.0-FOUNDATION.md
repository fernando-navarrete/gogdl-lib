# v1.1.0 — Foundation: tests, CI and CD

Work plan for the `v1.1.0` entry in [ROADMAP.md](ROADMAP.md). The goal is to make this crate
tested and gated before any feature work (`v1.2.0`+) starts, so everything after it lands with
tests and a pipeline. No change to the public API or to behavior in `v1.1.0` itself, so the bridge
(`gogdl_flutter`) and `lumen-cli` can move to it without touching their code.

The plan covers `v1.1.0` and its five follow-up patches (`v1.1.1`–`v1.1.5`, under **Patches**).
The branch goes into `main` only after `v1.1.5`. The plan is then condensed into
`devlog/v1.1.0-foundation.md` and deleted (see **After `v1.1.5`**), as the bridge did for its
`v1.2.0`.

GAPS items closed by `v1.1.0`: "Low — style / clippy" (the five never-read fields, every clippy
bullet, the unused import and the `v1.0.1` tag/`Cargo.toml` mismatch item, as far as it's about
future tags), and "Medium — missing coverage" (the first bullet, narrowed to what's still untested
afterwards). Closed by the patches: "Medium — cloud saves" refresh tokens in error strings
(`v1.1.1`), "Low — style / clippy" wrong-sign margin (`v1.1.2`), "Medium — Proton" 401 spin
(`v1.1.3`), a new "No downstream build check" item (added and closed by `v1.1.4`), and "Medium —
Proton" stale docs plus "Medium — missing coverage" no `CLAUDE.md` (`v1.1.5`). It also answers the
bridge's GAPS §7.1 (test-constructible types).

Tick each checkbox as it's done, one commit per phase (or smaller).

## Branch

All work happens on a new branch, created from `main` before Phase 0:

```sh
git switch main
git pull
git switch -c feat/v1.1.0-foundation
```

- Commit per phase (or smaller). Don't commit to `main` directly.
- Push the branch to `origin` so the CI jobs from Phase 5 can be run manually on it.
- Every tag (`v1.1.0` … `v1.1.5`) goes on a `feat/v1.1.0-foundation` commit. Consumers pin by git
  tag and tag pipelines run from the tag, so neither CI/CD nor the bridge's or `lumen-cli`'s pins
  need `main`.
- After `v1.1.5` (see **After `v1.1.5`**), merge into `main` with `git merge --ff-only`, so every
  tag's commit ends up in `main`'s history. No merge commit and no re-tagging.

## Phase 2 — HTTP test fixture and `download_files` tests

GAPS "Medium — missing coverage", first bullet. This is where the downloader regressions the GAPS
"standing facts" warn about get pinned.

- [x] **Decide (your call):** the test server. **Chosen: (b), as a raw `tokio` `TcpListener`
  rather than `hyper`** (`src/test_support.rs`). wiremock can't send part of a body and then hold
  the connection open, which the in-flight cancellation test needs.
  - (a) **Recommended.** `wiremock` as a dev-dependency: scripted responses per request count
    (fail N times, then succeed), and its own tokio runtime integration.
  - (b) A small `hyper`/`tokio` server under `src/test_support.rs` (`#[cfg(test)]`). No new
    dependency tree, more code to keep.
- [x] **Decide (your call):** how a test points the downloader at the server, since hosts are
  hardcoded.
  - (a) **Recommended.** In-crate `#[cfg(test)]` tests that seed `SecureLinksManager`'s cache (and
    the owned-products lookup it checks first) with links whose URLs point at the local server. A
    `#[cfg(test)]` constructor, no production change.
  - **Chosen: (a).** Seeded via `#[cfg(test)]` `SecureLinksManager::fixture_links` (served on every
    fetch, so an invalidation still refetches offline) and `lookups()` (counts attempts).
  - (b) Injectable base URLs on `HttpClient`. A real seam for later tests too, but it's API design
    that belongs with a minor, not this refactor-free release.
- [x] `tokio`'s `test-util` feature under `[dev-dependencies]` (`full` doesn't include it), so
  `backoff`'s sleeps can run under `tokio::time::pause`. Tests must not take real seconds.
- [x] `download_files` tests, in GAPS' order:
  - transport failure on attempts 0–4, then wrong-MD5 bytes on attempt 5 → `Err` (pins
    `attempt < MAX_ATTEMPTS - 4`). Write it first.
  - every attempt fails → `Err`.
  - wrong MD5, then good bytes → `Ok`, and the net byte total from the progress events equals the
    chunk size (pins `ProgressGuard`'s arithmetic).
  - one unit fails terminally while others are in flight → the batch returns `Err` without waiting
    for the rest, and the cancelled units' progress nets to zero (`6b4b7f3`).
  - the secure-link fetch fails with `ProductNotOwned` → characterizes today's six attempts. Name
    the test so `v1.2.0`'s change (return at once) is an obvious flip.

**Result:** the five tests plus one more (`bad_md5_is_only_retried_on_the_first_two_attempts`), 45
tests passing, 0.15s wall time, all against `127.0.0.1`. Test 1 as written doesn't pin `attempt <
MAX_ATTEMPTS - 4` (a mismatch on the last attempt is terminal under either condition); the extra
test does, and is the only one that fails when the condition is mutated to `!= MAX_ATTEMPTS - 1`.
The mismatch retry evicts the cached links, hence the fixture-links seam above.

**Done when:** the five tests pass in `cargo test`, offline, in well under a second of wall time.

## Patches

From ROADMAP's `v1.1.1+` list, done after `v1.1.0` on the same branch, in this order. Each is one
small session, one commit (or a few) and one tag. For each one: bump `version` in `Cargo.toml` with
`Cargo.lock`, tick the GAPS item with a "Fixed in `v1.1.x`: …" note, add a `CHANGELOG.md` section,
commit ("v1.1.x: …"), tag on the branch and check the tag pipeline goes green. Every patch is
additive or a fix, never a signature change (ROADMAP's rule). A behavior change is called out in
its `CHANGELOG.md` section.

### P1 — `v1.1.1`: no refresh tokens in error strings

GAPS "Medium — cloud saves", "Refresh tokens are sent in URL query strings…". Security, so it goes
first.

- [x] Call `.without_url()` on the `reqwest::Error` wherever a token-bearing request's error is
  converted: `AuthManager::refresh_auth` (`auth_manager.rs`, the `AuthError::ClientError { inner }`
  stringification) and `SavesAuth::get_saves_auth` (the `SavesError::ClientError` path). Check
  every other place `AUTH_URL`/`REFRESH_URL` are fetched (the login exchange too).
- [x] Only if GOG's token endpoint accepts it: POST the grant as a form body instead. Check with one
  manual request first; if it doesn't, stay with `.without_url()`.
- [x] Test: with the Phase 2 fixture, a transport failure on a token URL produces an error whose
  `Display` and `Debug` contain neither the refresh token nor the game's `client_secret`.
- [x] `CHANGELOG.md`: say consumers that logged these errors may have tokens in old logs.

**Result:** all three token exchanges (login, refresh, saves) are POSTs with a form body through
`HttpClient::post_token`, which strips the URL from its `reqwest::Error`s (GOG's endpoint answered a
POST like a GET on a bogus-token probe, and a live login, forced refresh and save listing all
worked). `AUTH_URL`/`REFRESH_URL` became `TOKEN_URL`, `CLIENT_ID`, `CLIENT_SECRET`, `REDIRECT_URI`.
4 new tests (88 in all, offline); removing `.without_url()` fails the `post_token` one. The
`ChunkServer` routes on the full path including the query, which the URL test needs.

**Done when:** the test passes and `grep` finds no token-bearing request whose error keeps its URL.

### P2 — `v1.1.2`: fix the expiry margin

GAPS "Low — style / clippy", "`Auth::is_valid`'s 60s margin has the wrong sign…". A behavior change:
tokens are refreshed up to 60s earlier.

- [x] One helper (e.g. `fn expires_after(valid_until, margin, now) -> bool`, `t - margin > now`)
  used by `Auth::is_valid` and `SavesAuth::is_valid`. Check `CdnUrlParams::is_valid` already has
  the right direction and use the helper there too if it fits.
- [x] Flip the Phase 3 boundary tests, and fix both doc comments to match the code.

**Result:** the crate-private `Expiring` trait (`src/client/auth/expiring.rs`) is implemented by
`Auth`, `SavesAuth` and `CdnUrlParams`, each supplying its deadline and whether a missing one counts
as fresh. The Phase 3 tables flipped (only +61s is valid now) and `CdnUrlParams` got its own table
(it had none): 69 unit tests, 90 in all, offline. Flipping the margin's sign in the trait fails
all three tables.

**Done when:** the flipped tests pass and all three `is_valid`s agree.

### P3 — `v1.1.3`: unauthenticated 401 returns at once

GAPS "Medium — Proton", "`HttpClient::fetch` spins on a 401 when `require_auth` is `false`…".

- [x] In `HttpClient::fetch`'s `HttpError` arm, when `require_auth` is `false`, return
  `ClientError::HttpError` with the status and body instead of falling through the loop.
- [x] Fix `GogDl::get_proton_releases`' rustdoc ("only retries a 401 or a transport error").
- [x] Test with the fixture: an unauthenticated fetch that gets a 401 makes one request and returns

**Result:** `fetch` returns `HttpError { status, body }` on any non-success status unless a refresh
applies. 3 new tests in `client/http.rs` (401 with body intact after one request, 503 once, transport

pins the actual behavior.

**Done when:** the test passes and the GitHub fetches no longer loop on a 401.
