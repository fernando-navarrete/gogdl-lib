# v1.2.0 — Download management

Work plan for the `v1.2.0` entry in [ROADMAP.md](ROADMAP.md): everything the bridge's `v1.3.0`
(`../gogdl_flutter/v1.3.0-DOWNLOADS.md`, "Dependencies on `gogdl-lib`") and Lumen's `v1.3.0`
(`../lumen/v1.3.0-DOWNLOAD-MANAGEMENT.md`, D4–D7) ask of this crate. The bridge ships a fallback for
every item and picks each one up as its own `v1.3.x` patch, so nothing here blocks it, except
Lumen's free-space check (see **Phase 0**).

`v1.2.0` is a **breaking** minor: the free-space errors gain fields, a few types become exported or
`#[non_exhaustive]`, and `download_proton_release` stages its extraction. Nothing is removed. It
ships with the bridge change that adopts it (ROADMAP's rule).

The plan covers `v1.2.0` and its three follow-up patches (`v1.2.1`–`v1.2.3`, under **Patches**). It
ends with the `v1.2.3` tag and a fast-forward merge into `main` (see **After `v1.2.3`**). Writing
`devlog/v1.2.0-download-management.md` and deleting this plan is the next step on `main`, as for
`v1.1.0`, and is not part of this plan.

GAPS items closed by `v1.2.0`: "Low — style / clippy" free-space error detail; "Medium —
duplication & consistency" `MAX_ATTEMPTS`/retry split, hand-copied retry loops and the dead
`AuthError` arm, deterministic secure-link failures, and the unexported `DepotFile`/`Chunk`/
`DownloadUnit`/`FileSystemError`; "Medium — cloud saves" save truncation; "Medium — Proton"
re-download overlay; and the Proton and saves parts of "Medium — missing coverage". Closed by the
patches: "`repair` checksums the chunks of files it has just allocated" (`v1.2.1`), "`Downloader::
repair` is a near-verbatim copy of `Downloader::download`" (`v1.2.2`), and "`DownloadEvent::Progress`
reports compressed wire bytes…" plus "`Preparing`/`Prepared` are emitted back-to-back" (`v1.2.3`).
It also answers bridge GAPS §7.2, §7.3 (download part), §7.4, §7.6 (truncation) and §7.10, and
Lumen D4–D7.

Tick each checkbox as it's done, one commit per phase (or smaller).

## Patches

From ROADMAP's `v1.2.1+` list, done after `v1.2.0` on the same branch, in this order. Each is one

### P1 — `v1.2.1`: `repair` skips checksumming files it just allocated

allocated". Resume speed for Lumen's "resume interrupted downloads".

- [x] Units of files allocated in stage 2 go straight to the download list, without an MD5.
  Done, but only for chunks past the file's old length (**decided**): `set_len` keeps a resized
  file's existing bytes, so those below it are still hashed. A missing file skips entirely.
- [x] They still get their `VerificationEvent` (`ChecksumMismatch(path, size)`, which is what the
  all-zero range produced before), so a consumer counting verification events sees the same number.
  Say so in a comment and in the rustdoc of `VerificationStage`.
- [x] Test: repair over an empty directory hashes nothing (count `compute_chunk_checksum` calls
  through a `#[cfg(test)]` counter) and emits one event per unit, as before. Done, plus
  `repair_hashes_only_below_a_files_old_length`. **Accepted:** a chunk of real all-zero content used
  to verify and is now re-fetched (CHANGELOG, `VerificationStage` rustdoc).

**Done when:** the test passes and the event count is unchanged.
