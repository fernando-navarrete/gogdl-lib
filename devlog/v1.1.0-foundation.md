# Devlog — v1.1.0 Foundation

Tests, CI and CD from the `v1.1.0` ROADMAP entry, plus the `v1.1.1`–`v1.1.5` follow-up patches. Ran
as eight phases and five patches; kept here for the decisions and pitfalls that aren't obvious from
the diff. `v1.1.0` changed no public API and no behavior, so the bridge and `lumen-cli` only had to
move their pin. The patches are marked in `CHANGELOG.md` where they change behavior. The line went
into `main` by fast-forward, so every tag's commit is in `main`'s history.

## Phase 0 — Branch and baseline

Baseline on `1.98.1`: 6 rustc warnings, 48 clippy warnings (`--all-targets`), 39 tests, 0 doctests.
GAPS' header was refreshed first, since it still described `1.0.10`.

## Phase 1 — Green gates and toolchain pin

Pure style, so no tests. The pin matches the bridge's (`1.98.1`). Module inception was fixed by
renaming the private inner modules (`client::client` → `client::http`), invisible to consumers.
`produt_type` became `product_type` with `#[serde(rename = "type")]`; the silent drop of failed
`gamesdb` lookups stays for `v1.3.0`.

## Phase 2 — HTTP fixture and `download_files` tests

**Decision:** a raw `tokio` `TcpListener` (`src/test_support.rs`) instead of `wiremock`, because
wiremock can't send part of a body and then hold the connection open, which the in-flight
cancellation test needs.

**Decision:** tests reach the fixture by seeding `SecureLinksManager`'s cache (`fixture_links`,
`lookups()`), not through injectable base URLs. That would be API design and belongs in a minor.
`fixture_links` is served on every fetch because a MD5-mismatch retry evicts the cached links and
refetches.

**Pitfall:** the planned first test doesn't pin `attempt < MAX_ATTEMPTS - 4` (a mismatch on the last
attempt is terminal either way). `bad_md5_is_only_retried_on_the_first_two_attempts` does, and is
the only test that fails when the condition is mutated. `tokio`'s `test-util` isn't in `full`, so
it's a dev-dependency feature.

## Phase 3 — Pure-logic and deserialization tests

`refresh_auth` persisting `valid_until` is **skipped**: it needs the hardcoded token endpoint, so it
waits for injectable hosts. Fixtures under `tests/fixtures/` are captures of the live services with
secrets and account ids scrubbed (synthetic save hashes). GOG types a collection as `spam`, not
`pack`. The owned-games filter moved into a private `keep_games` so it's testable offline, chain
unchanged. Cyberpunk's `saves` location showed that slots like `AutoSave-0` must survive
`relative_path_in`.

## Phase 4 — Test-constructible public types

Everything was already constructible from outside the crate, so nothing needed a fix. The finding:
no event enum or Proton type derives `Debug`/`PartialEq`, so outside tests use `matches!` (a GAPS
item, additive fix later). `tests/public_types.rs` matches every event through an exhaustive
`match`, so a new variant breaks the build. GOG's real `productType` is upper case (`GAME`, `DLC`);
the rustdoc said lower case and was fixed.

## Phase 5 — CI

Reused the bridge's setup. The image is built on the runner host (`ci/build-image.sh`), which shares
docker through its socket, so jobs see it directly. A `.toolchain` check fails a job on a stale
image. Trigger policy is tags plus manual web runs. Confirmed red with an unused variable, a failing
assert and a broken intra-doc link on a scratch branch. Cosmetic: the cache step warns that
`.ci/cargo/git/` is empty, since the crate has no git dependencies.

## Phase 6 — CD

`CHANGELOG.md` was backfilled per `v1.0.x` tag, with **Breaking** and **Behavior change** marks
checked against each tag's diff (1.0.4, 1.0.6 and 1.0.9 change signatures; 1.0.10's Proton rename
and 1.0.11's `get_owned_games` change behavior). `v1.0.1` was tagged with `1.0.0` in `Cargo.toml`.
`tool/release_notes.sh` fails unless the tag, `Cargo.toml`, `Cargo.lock` and a non-empty changelog
section agree.

**Pitfall:** the `release` job can't reach the GitLab host until it trusts the runner's CA
(`CI_SERVER_TLS_CA_FILE`). Verified with a scratch `v1.0.99` tag: mismatch failed, a matching bump
created a release with the right notes; tag, branch and release were deleted.

## Phase 7 — Release `v1.1.0`

Tagged on the feature branch, not `main`: tag pipelines run from the tag and consumers pin by tag.
The toolchain pin applies to this repo only, since cargo ignores a dependency's
`rust-toolchain.toml`. `lumen-cli` (103 tests) and the bridge (41 tests) built against it with no
change; `lumen-cli`'s interactive menu needs a TTY and wasn't driven.

## P1 — `v1.1.1`: no refresh tokens in error strings

All three token exchanges (login, refresh, saves) became form-body POSTs through
`HttpClient::post_token`, which strips the URL from its `reqwest::Error`s. GOG's endpoint accepted a
POST after one manual probe, and a live login, refresh and save listing worked. `.without_url()` is
the part the test pins. Consumers that logged the old errors may have tokens in old logs.

## P2 — `v1.1.2`: the expiry margin

The 60s margin had the wrong sign. The crate-private `Expiring` trait
(`src/client/auth/expiring.rs`) gives `Auth`, `SavesAuth` and `CdnUrlParams` one `is_valid`, each
supplying its deadline and whether a missing one counts as fresh. A behavior change: tokens refresh
up to 60s earlier.

## P3 — `v1.1.3`: unauthenticated 401

`fetch` returns `HttpError { status, body }` on any non-success status unless a refresh applies.
**Pitfall:** the plan assumed 5xx retries; it doesn't (only transport errors do, since `5b7ca2f`),
so the test pins the actual behavior.

## P4 — `v1.1.4`: downstream build check

**Decision:** one read-only deploy key (`DOWNSTREAM_DEPLOY_KEY_B64`, masked and **unprotected**),
enabled on `lumen-cli`, `gogdl_flutter` and `gogdl-lib`. ssh offers the agent's first key and
doesn't fall back, so two keys for one host fail the second project. `LUMEN_CLI_REF`/`BRIDGE_REF`
replace "their `main`", since `lumen-cli`'s `main` pins `v1.0.4`. `RUSTUP_TOOLCHAIN` forces this
image's Rust.

**Pitfall:** the `[patch]` is ignored ("was not used in the crate graph") until `cargo update -p
gogdl-lib` re-locks the consumers. The image also lacked `openssh-client`. The bridge's `cargo test`
needs no Flutter. A scratch branch renaming `get_owned_games` turned the job red.

## P5 — `v1.1.5`: stale docs and `CLAUDE.md`

The `User-Agent` requirement was gone from the code since `7a57534`; the docs now agree. The four
saves methods return `SavesError`, not `GogDlError`, and the docs say so (the variant is breaking,
so GAPS' item stays open for `v1.4.0`). Reading the rendered docs found one more stale claim,
`AuthError::TokenExpired` ("callers never see this"). `CLAUDE.md` lists all 25 public `GogDl`
methods.
