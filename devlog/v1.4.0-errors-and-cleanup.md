# Devlog — v1.4.0 Errors and API cleanup

What the bridge's `v1.5.0` asked of this crate: a status-aware `AuthError`, `GogDlError::SavesError`,
`#[non_exhaustive]` on the last six error enums, and the removals earlier releases scheduled here.
Ran as steps 0–14 of a work plan (deleted with this devlog), then the patches `v1.4.1`–`v1.4.3`. Each
step was one branch and one squash MR. `v1.4.0` is a **breaking** minor and ships with the bridge
change that adopts it. SHAs are commits on `main`: `fd09d7a` (plan), `7277e32` (token-error
fixtures), `8f1d564`, `eb9e098`, `6fc192e`, `148067e`, `65e0d63`, `097187d`, `2ddb3db`, `be9b385`,
then the releases `94140a0` (`v1.4.0`), `e34126d` (`v1.4.1`), `56d7f0c` (`v1.4.2`) and `ca89691`
(`v1.4.3`). `4e2f798` (CI) came in between.

## Decisions

- **D1, `AuthError` has no strings.** `ClientError { inner }` became `InvalidLoginCode`,
  `SessionRevoked`, `NetworkError(reqwest::Error)`, `Rejected { status, body }` and
  `InvalidResponse(serde_json::Error)`. **The grant decides** between the first two, not the body:
  `invalid_grant` on `authorization_code` is a bad or expired code, on `refresh_token` a revoked
  session. GOG tells a bad code from an expired one only in `error_description`, which is kept for
  the bridge's message. Turned down: keep `ClientError { inner }` and add two kinds; the network case
  would stay a string, which Lumen's Phase 0 found it can't map.
- **D2, the saves grant** goes through the same classifier, so a dead session there is
  `SavesError::ClientError(ClientError::AuthError(SessionRevoked { .. }))`. Not breaking at the type
  level, but a behavior change, and the CHANGELOG says so. A 401 on the storage side still doesn't
  evict the cached grant; that stays open for `v1.5.0`.
- **D3, `#[non_exhaustive]` on all six** (`GogDlError`, `ClientError`, `AuthError`, `GamesError`,
  `DepotError`, `SecureLinksError`), before the variants changed, so this is the last breaking error
  release: a new variant is additive from here. All six are in `variant_guard.rs` with no wildcard.
- **D4, `repair_game` is deprecated, not removed.** It has done what `download_game` does since
  `v1.3.0`. It goes in `v1.5.0`. The deprecation fails a `clippy -D warnings` build, so it counts as
  breaking for the bridge. Turned down: keep both names and say so, which leaves two names for one
  operation for good. The internal `DownloadManager::repair_game`, a copy with the facade as its only
  caller, was deleted outright.
- **D5, the `src/fs/` items are `pub(crate)`.** Nothing outside could name them, so it isn't breaking;
  exporting them would have committed the crate to `PathResolver`'s API.
- **D6, a `?` that reaches a dead variant** counts as evidence it is live. None did: no `?` stopped
  compiling when the variants went.

## What GOG answers

Captured against the real endpoint on a throwaway session (step 1):

| Case | Grant | Status | `error` |
|---|---|---|---|
| Bad login code | `authorization_code` | 400 | `invalid_grant` |
| Garbage refresh token | `refresh_token` | 400 | `invalid_grant` |
| Same, with a game's client | `refresh_token` | 400 | `invalid_grant` |

An expired code is the same `400 invalid_grant`. The body carries the client id, never a token, so
`description` is safe to keep in the error. **Refresh tokens did not rotate**: a refresh returned the
same one, so replaying "the old token" succeeded and there is no rotated-out failure to pin
(`TokenObserver` still fires per refresh). No 5xx could be had, so `Rejected` has only been tested
with a scripted status.

## Pitfalls

- `AuthManager::exchange` had an `Err(ClientError::AuthError(e))` arm that `post_token` could never
  build. It went with the string. `From<TokenFailure> for ClientError` had no other caller and was
  deleted, and `Grant` is `pub(crate)`.
- The removed variants' only constructors were in `PathResolver`: `get_file_size` now returns
  `io::Result<u64>` (the engine discarded the error) and `allocate_file` reports its open and
  `set_len` failures as `FileOpenError`. `DownloadError::DeflateError` stayed; `engine.rs` builds it.
- Removing `Preparing`/`Prepared` left one sequence test to change, not two: `download_game` and
  `repair_game` had converged. `Started` is now the stage's first event.
- Step 8 surfaced dead code once the 14 "not reachable from outside" methods went `pub(crate)`:
  `SavesAuth`'s `refresh_token`, `token_type`, `session_id` and `scope` were never read, and
  `SecureLinksManager::is_valid` became `#[cfg(test)]`. `-W unreachable_pub` still flags 139 sites
  (managers, `secure_links`, `constants`, `downloader/util`, `engine.rs`); open in GAPS "Low".
- The `downstream` job now patches the GitHub mirror, which is what the bridge pins, and no longer
  builds `lumen-cli` (`4e2f798`).

## Downstream breaks

Recorded per step, not fixed from this plan (decided 2026-10-16: `gogdl_flutter` and `lumen-cli` are
not touched from here). In the bridge: 13 errors in `src/error_kind.rs` (the `NetworkError`/`Http`
arms, the tests that build them, `FileCreationError`, `AuthError::ClientError`, and E0004 on the
`GogDlError` match, which needs a wildcard and a `SavesError` arm); four in
`progress/{download,repair}.rs` (tests that emit `Preparing`/`Prepared`); and the `repair_game` call
at `api/gogdl.rs:535` under `clippy -D warnings`. Removing the dead variants and the two events broke
nothing else there. `lumen-cli` uses `GameBuilds.game_title` (`model.rs:66`, `ui/menu.rs:641,717`) and
still pins `v1.0.10`.

## Patches

- **`v1.4.1`:** one `HttpClient::stream_url(url, headers)` replaces `stream_chunk` and
  `stream_chunk_with_headers`, and one `send_checked` holds the status check that `get_json`,
  `get_and_decode`, `get_json_with_auth`, `post_token`, `put_stream` and the stream shared.
  `GITHUB_API_HEADERS` is one const. `post_token` still strips the URL.
- **`v1.4.2`:** `stream_url` writes to an `AsyncWrite` sink instead of calling a boxed callback, so
  the chunk decoder and the Proton duplex writer lose their `tokio::sync::Mutex` and per-read
  `Box::pin`. The `.map(|unit| unit.clone().unwrap().clone())` pairs in `engine.rs` are
  `.into_iter().flatten().collect()`.
- **`v1.4.3`:** `rand` is `default-features = false, features = ["sys_rng"]`; `thread_rng` pulls in
  `std_rng` (chacha20) and saves nothing, so the three call sites draw from one `sys_rng()` in
  `retry.rs`. `tar` drops `xattr`: `unpack_xattrs` already defaults to `false` and `src/` never sets
  it, so extraction is unchanged and the tarball check was skipped. `cargo tree -e normal` went from
  308 to 300 lines; five crates left `Cargo.lock`, none was added.
