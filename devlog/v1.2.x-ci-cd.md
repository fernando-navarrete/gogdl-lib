# Devlog — v1.2.x CI/CD and supply chain

Brought this repo's CI/CD up to what `../metatrader-dashboard` runs, adapted to a Rust library, plus a
push mirror to GitHub, ending with `main` and the `v*` tags protected. Ran as steps 0–13 of a work plan
(deleted with this devlog); each step was one branch and one squash MR. No crate code or public API
changed, so there was no release: `Cargo.toml` stays at `1.2.3` until `v1.3.0`. SHAs below are the
commits on `main`. Kept here for the decisions and pitfalls that aren't obvious from the diff.

## Step 0 — Decisions

- **D1 merge method:** fast-forward with squash required, source branch deleted, squash message = MR
  title. One step = one commit on `main`; devlogs cite SHAs on `main`, never branch SHAs.
- **D2 tags:** on `main`, after the release MR merges (a protected `main` plus any other MR landing
  first would otherwise orphan a tag cut on a branch). Consumers needing unreleased work use the manual
  `downstream` job or a `rev =` pin on their own branch.
- **D3 runner load:** accept three builds per push (`lint`, `test`, `doc`), with `interruptible` and
  auto-cancel.
- **D4 toolchain bumps:** Renovate opens them alone, never grouped. The MR stays red on the
  `.toolchain` check until the image is rebuilt by hand; the red pipeline is the reminder.
- **D5 range strategy:** `update-lockfile`. Consumers resolve their own lockfiles, so Renovate only
  touches `Cargo.lock`, and a raised floor in `Cargo.toml` is a release decision.
- **D6 mirror:** public, `MIT OR Apache-2.0`. The Galaxy client id/secret in `src/constants/mod.rs` are
  the public values every open-source GOG client ships.
- **D7 mirror push:** GitLab's built-in push mirror, so the token is in the mirror settings and no CI
  job can read it.
- **D8 lint scope:** unchanged (fmt + `clippy -D warnings`), `cargo deny` as its own job.

## Step 1 — Pipelines on MRs and `main` (`e01ebf2`)

Pipelines run on MRs, `main`, `vX.Y.Z` tags and manual web runs; a branch with an open MR runs only the
MR pipeline, a branch without one runs nothing. `downstream` stays manual and `allow_failure`.

## Step 2 — Pre-commit hook (`8ff8502`)

`cargo fmt --check` only. A hook that formats and re-stages can commit half of a partly staged file.

## Step 3 — Pin images by digest (`e3476df`)

`release-cli` publishes a single-arch manifest, not an index, so the pinned digest is of that manifest.
`rustup-init` is downloaded at a pinned version and checked against its `.sha256`. The image tag gained a
revision (`-rN`) because the image now changes without the channel changing; the `.toolchain` check still
compares the channel only.

## Step 4 — `cargo-deny` (`40cceb1`)

**Pitfall:** `cargo-deny` checks only crates in the build graph. `ring` sits in `Cargo.lock` but no
enabled feature pulls it in, so it can't serve as a bite test. The first real run found RUSTSEC-2026-0285
in `rustls 0.23.41`, fixed with `cargo update -p rustls --precise 0.23.45`; restoring `main`'s old
`Cargo.lock` in a throwaway MR made `audit` red. `deny.toml` has no `ignore` entries.

## Step 5 — OSV-Scanner (`66380a9`)

Fails only on a `MAL-` id; CVE/GHSA/RUSTSEC findings are printed but gated by `audit`, so each finding
has one failing gate. The "Weekly scan" schedule (`SCHEDULE=scan`) runs `audit` and `scan` only.

## Step 6 — Secret scan (`1950927`)

Full-history audit before the mirror: 238 commits, all refs, no findings, so `.gitleaks.toml` has no
allowlist. On MRs `secrets` scans `$CI_MERGE_REQUEST_DIFF_BASE_SHA..HEAD`; on `main` and tags the whole
history. Bite test: a fake `ghp_` token in a throwaway MR (24) turned `secrets` red; closed unmerged
and the branch deleted, so no ref reaches the commit.

## Step 7 — `SECURITY.md` (`89bc280`)

Cargo has no `ignore-scripts`: a `build.rs` or proc macro runs on every machine and CI job, so the
policy asks the MR to name new crates that have one.

## Step 8 — `renovate.json` (`3a40384`)

**Decision:** 0.x minors are treated as majors (`sysinfo`, `rand`, `async-compression` break on a
minor). `lockFileMaintenance` is off because it runs a plain `cargo update`, bypassing the 7-day age
check for every transitive crate.

## Step 9 — Renovate job (`fa66150`, first MR `cfbb7d4`)

- The pinned Renovate image is the slim one without `cargo`; containerbase installs Rust on demand and
  ignores `rust-toolchain.toml`, taking the latest stable. `constraints.rust` pins it, and the toolchain
  regex manager bumps it, so one MR moves both.
- **Pitfall:** protected variables reach only protected refs, so `main` had to be protected during this
  step (step 12's first bullet) or the first run failed with "RENOVATE_TOKEN is not set".
- Bite test: jobs printing `${RENOVATE_TOKEN:+set}` on an unprotected branch, with and without
  `environment: renovate`, print nothing.

## Step 10 — Release flow (`717cd25`)

`release` needs all check jobs and fails unless the tagged commit is an ancestor of `origin/main`. It is
first exercised by `v1.3.0`; only `tool/release_notes.sh v1.2.3` and the pinned image were checked.

## Step 11 — GitHub mirror (`87c8650`)

The `v*` tags mirrored even with "Mirror only protected branches" on and the tags still unprotected.
`repository` in `Cargo.toml` is the GitHub URL because the GitLab host is LAN-only.

## Step 12 — Protect `main` and `v*` (`497f596`, plus settings)

**Pitfall:** the tag bite test first ran before `v*` was protected, and both the delete and a force-move
succeeded; `v1.2.3` was restored to `988011c` within seconds on GitLab. The mirror had already pushed the
moved tag, though, and GitHub's `v*` ruleset rejected the restore, so GitHub kept `v1.2.3` at the
throwaway `51075b0` until 2026-10-08, when the ruleset was turned off for one "Update now". Check that a
tag is listed under Protected tags *before* trying to delete one, and after any tag restore, compare
`git ls-remote` on both remotes. After protecting, both were rejected by the pre-receive hook. A direct
push to `main` is rejected, and an MR with a failing test (22) can't be merged.
