# v1.3.0 — Library and account

Work plan for the `v1.3.0` entry in [ROADMAP.md](ROADMAP.md): owned games that don't silently
shrink, `download_game` skipping chunks that already verify, cheaper library lookups, one "not a
game" answer across the fetchers, and no mutex held across a network call. Nobody blocks on it: the
bridge's `v1.4.0` needs only `clear_cache` and `remove_products`, which ship ahead as the additive
patches `v1.2.4` and `v1.2.5`. The bridge picks `v1.3.0` up later as a `v1.4.x` patch, absorbing it
without a Dart change (a translator stage for `VerificationStage`, `OwnedGames.unresolved`), and
`lumen-cli` gets its first bump since `v1.0.10`.

`v1.3.0` is a **breaking** minor: `OwnedGames` gains a field, `download_game`'s events gain a
`VerificationStage`, and `get_game_builds`/`get_game_links`/`get_game_summary` on a non-game return
`ProductNotAGame` instead of a decode error. Nothing is removed. It ships with the bridge change that
adopts it (ROADMAP's rule).

The plan covers `v1.3.0` and its two follow-up patches (`v1.3.1`, `v1.3.2`, under **Patches**), and
ends with writing `devlog/v1.3.0-library.md` and deleting this file (step 14).

GAPS items closed by `v1.3.0`: "Medium — owned games" silent drops, per-call `gamesdb` re-fetch, and
the game/non-game decision; "Medium — duplication & consistency" `download` re-downloading every
chunk, uncollapsed secure-link fetches, "not a game" handling, and caching between depot and saves
data; "Medium — cloud saves" `SavesManager` holding its mutex across round-trips. Closed by the
patches: "`GameScreenshots::resolve_links` picks a magic formatter index" (`v1.3.1`) and
"`GameDetails.id` and `GameBuilds.game_title` are never assigned" (`v1.3.2`). Also "Low — CI/CD",
"The `release` job's `needs` and on-`main` rule are untested", if `v1.2.4` hasn't already exercised
it.

Each step is one branch and one small MR into `main` (fast-forward with squash, so one commit per
step on `main`). Tick each checkbox as it's done.

## Starting point (2026-10-11)

- `main` at `2c4e536` ("Docs: schedule the bridge's v1.4.0 requests"), `Cargo.toml` at `1.2.3`,
  newest tag `v1.2.3`. Toolchain `1.98.1`, CI image `gogdl-lib-ci:rust-1.98.1-r3`.
- `cargo test --locked`: 110 unit tests, 12 integration tests (`tests/public_types.rs`), 12 doctests,
  all offline, all green.
- Not yet shipped: `v1.2.4` (`clear_cache`) and `v1.2.5` (`remove_products`), both ahead of this in
  ROADMAP. Steps 4–6 need to know what `clear_cache` drops, and steps 8–10 make `main` unable to cut
  another `v1.2.x` (see **D1**).
- Consumers: the bridge pins `v1.2.3` (GitHub mirror) and is on its `v1.4.0` plan; `lumen-cli` pins
  `v1.0.10` (`../lumen-cli/Cargo.toml:12`), so its bump crosses the `v1.0.11` `get_owned_games`
  behavior change and every `v1.2.0` break.
- Owned games: `OwnedGames::get_owned_games` (`src/games/owned_games.rs`) fetches
  `gamesdb.gog.com/platforms/gog/external_releases/{id}` per owned product, unauthenticated,
  `buffer_unordered(2)`, uncached, and `keep_games` drops every failed lookup.
  `a_failed_lookup_for_a_game_drops_it_silently` pins that and is named to be flipped. `OwnedGames`
  is `{ owned: Vec<ProductId> }`, `Serialize`/`Deserialize`, not `#[non_exhaustive]`, and not in
  `tests/public_types.rs`.
- Not a game: only `GameDetails::get_game_details` returns `GamesError::ProductNotAGame` (from a
  cached `None`). `GameBuilds`, `GameLinks` and `GameSummary` surface whatever `fetch` fails with.
- Caches: `GamesManagerInner` caches details, links, builds, summary and screenshots per id, plus the
  owned-products list. `DepotManagerInner` caches only `ProductDetails`; `BuildMetadata` and
  `DepotInfo` are fetched every time (`get_product_bundles` re-fetches both). `SavesManagerInner`
  caches `GameSaveIds` and `SavesAuth`, not `RemoteConfig`.
- Mutex across the network, five places of the same shape:
  `SecureLinksManager::get_secure_links` awaits `get_owned_products()` under its lock
  (`src/secure_links/links_manager.rs`); `GameSaveIds::get_game_save_ids` awaits `get_game_builds`
  and `get_build_metadata` under `SavesManager`'s (`src/saves/game_save_ids.rs`); and
  `DownloadManager` does it three times under its own: `get_build_metadata`
  (`src/downloader/download_manager.rs:55-67`), `get_depot_info` in `product_bundle.rs:68-71`, and
  `get_owned_products` in `downloadable_product.rs:56-59` (none in GAPS before step 0).
- Secure links: no in-flight dedup; the cache check and the fetch aren't one critical section.
  `lookups()` counts calls, not fetches.
- Downloads: `Downloader::pipeline` takes `Units::All` (`download`, no `VerificationStage`) or
  `Units::Verified` (`repair`) (`src/downloader/engine.rs:28-32,155-200`).
  `download_stage_sequence` and `repair_stage_sequence` pin both event sequences.

      **Decided (2026-10-11):** as recommended; step 7's captures decide.
- [x] **D4. What `download_game` becomes.** *Recommended:* `download` runs `Units::Verified`, so it
      verifies, then fetches what's missing, exactly like `repair_game`. The two methods then do the

      `v1.4.0` entry for discussion. The alternative, verify only files whose size already matches,

- [x] **D5. What `clear_cache` drops among the new caches.** *Recommended:* keep anything keyed by an

- [x] `SavesManager`: same for `depot` and `games`; `SavesManagerInner` keeps the two `HashMap`s.

- [x] `DownloadManager`: same for `depot`, `secure_links` and `games`; `DownloadManagerInner` keeps
      `downloadable_products`, so `get_build_metadata`, `product_bundle.rs`'s `get_depot_info` loop and

- [x] Test, one per manager (saves, downloads, secure links): the test holds `GamesManager.inner`
      itself, so a cold call parks at the await the outer lock used to span, and a call for an
      already-cached game completes under `start_paused` and a timeout. A fixture server can't do it:
      `get_game_builds` fetches the hardcoded `content-system.gog.com`. Each test fails if the old
      lock is put back.
- [x] `grep -n 'lock().await' src` and check nothing left awaits a fetch while holding one.

**Done when:** the test passes and the GAPS item is ticked ("Fixed in `v1.3.0`: …").

## Step 2: Collapse concurrent secure-link fetches

GAPS "Medium — duplication & consistency", "Secure-link fetches aren't collapsed".

- [x] Add a `#[cfg(test)]` fetch counter next to `lookups()`, counting fetches (fixture or real), not
      calls.
- [x] A per-`game_id` in-flight cell (the `Arc<OnceCell<_>>` shape `PathResolver::dir_cache` uses),
      so the ownership check and the fetch run once for N concurrent callers. Invalidation replaces
      the cell, so the next caller after an eviction starts a fresh fetch, and an expired entry is
      replaced the same way.
- [x] `invalidate_secure_links` takes the set the caller used and evicts only if it is still the
      cached one, so a late 401 doesn't evict a sibling's fresh fetch. The engine's fetch-error path
      no longer invalidates (nothing was cached).
- [x] A failed fetch isn't cached. `SecureLinksError` isn't `Clone`, so waiters can't share the
      leader's error without a new public variant (breaking); the queued waiters retry one at a
      time instead, each with its own error.
- [x] Tests: N concurrent `get_secure_links` on a cold cache → one fetch; N racing past an expired
      entry → one fetch; a failing fetch → one caller errs, the next waiter retries (never two at once), and the failure isn't cached; a stale invalidation keeps a fresher set.
- [x] Every existing `download_files` test passes unchanged.

**Done when:** the three tests pass and the GAPS item is ticked.
